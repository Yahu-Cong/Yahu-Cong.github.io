CS180 Project 1

Overview

This project aligns and colorizes Sergei Prokudin-Gorskii's glass plate scans.

Part 1: Single-scale alignment (L2 loss)

best_shift exhaustively searches a ±15 pixel window and scores each candidate shift with raw-pixel L2/SSD loss. This is only practical on the small JPEG scans.

cathedral.jpg: shift_g = (dy=1, dx=−1), shift_r = (dy=7, dx=−1)

monastery.jpg: shift_g = (dy=−6, dx=0), shift_r = (dy=9, dx=1)

tobolsk.jpg: shift_g = (dy=3, dx=2), shift_r = (dy=6, dx=3)

Part 2: Multi-scale pyramid alignment on all provided images

Each image goes through the same five-step pipeline (pyramid_alignment in the notebook): first a color-balancing transform, then per-channel histogram contrasting, then white balancing, then the green and red channels are aligned to the blue channel via the coarse-to-fine pyramid search (scored with a gradient-based loss instead of raw pixel L2, more robust to the plates' brightness/exposure differences), then the result is automatically cropped to remove the plate border.

Part 4: Failure cases

Two images did not align well: ilemselga.jpg and monastery.jpg.

ilemselga.jpg: visible ghosting across the whole scene

monastery.jpg: visible ghosting across the whole scene

monastery.jpg: checking the raw channels directly, the blue plate's sky is badly overexposed and almost featureless, while the green and red skies still show clear cloud detail. Blue is the reference channel everything else aligns to, so a sky that's essentially flat and blown out leaves very little gradient signal there for the aligner to match against.

ilemselga.jpg: both the green and red plates have darkening in their top corners that the blue plate doesn't share. That corner darkening in two of the three plates but not the reference distorts the gradient comparison near the top of the frame.

Part 5: Bells and whistles

Five tricks on top of the base alignment, shown here in the order pyramid_alignment actually applies them. Each one below is before/after on emir.tif.

1. Better color mapping

Motivation: the raw channel stack has a residual color cast that a straight RGB stack doesn't fix. Approach: a small per-pixel 3×3 channel-mixing transform, c' = M c for each pixel's color vector c = (r, g, b), where M has 1 + alpha on the diagonal and -alpha / 2 off the diagonal.

Before

After

2. Automatic contrasting

Motivation: each channel may not be using its full brightness range. Approach: per-channel histogram equalization, output = CDF(input), where CDF(v) is the fraction of that channel's pixels at or below value v.

Before

After

3. Automatic white balance

Motivation: the three plates can differ in overall brightness. Approach: grey-world rescaling, c' = c * (grey / mean(c)) per channel, where grey is the average of all three channels' means.

Before

After

4. Better features

Motivation: raw-pixel L2/SSD (sum((I1 - I2)^2)) is sensitive to brightness/contrast differences between plates and lets large smooth low-frequency regions (sky, walls) dominate the loss over the structure that actually needs to line up. Approach: score shifts on unit-normalized image gradients instead, sum((grad(I1) - grad(I2))^2), which keeps the comparison focused on edges/structure.

Before (misaligned)

After

5. Automatic cropping

Motivation: every plate has a dark border around the actual photo that a fixed crop can't reliably remove across scans of different sizes. Approach: for a candidate border width w, score it as score(w) = mean(edge strength in border) - mean(edge strength in interior), using a smoothed edge-strength profile along each side, and pick the w that maximizes it.
